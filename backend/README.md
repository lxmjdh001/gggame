# 游戏业务后端（Go）

这是独立于号码生成器的业务模块，管理场次、周期映射、开奖记录和首次模拟历史。数据库：`data/games.db`（bbolt）。

## 三层结构

```text
Vue 前端 :5173
  └─ /api 反向代理 → Go 业务后端 :8082
                        └─ HTTP → Go 号码源 :8081
```

号码源每天北京时间00:00一次性生成当天1440批 `g1..g8`；业务后端鉴权预取并持久化至私有缓存，按相同开奖期号映射，到对应分钟第05秒才发布。前端每秒同步当前场次与最近 100 期，倒计时使用服务器时间校准。

## 场次规则

位置从 1 开始。

| 场次 ID | 游戏 | 周期 / 开奖时间（北京时间） | 来源 | 位置 |
| --- | --- | --- | --- | --- |
| ssc-10 | 时时彩 | 10 分钟 | g2 | 1,2,3,4,5 |
| ffc-1 | 分分彩 | 1 分钟 | g1 | 1,2,3,4,5 |
| ffc-3 | 分分彩 | 3 分钟 | g1 | 6,7,8,9,10 |
| ffc-5 | 分分彩 | 5 分钟 | g1 | 3,4,5,6,7 |
| k3-1 | 快3 | 1 分钟 | g8 | 1,2,3 |
| k3-3 | 快3 | 3 分钟 | g8 | 8,9,10 |
| k3-5 | 快3 | 5 分钟 | g8 | 4,5,6 |
| pk10-10 | PK10 | 10 分钟 | g6 | 1–10 全部 |
| lhc-daily | 澳门六合彩 | **每天 21:30** | g7 | 1–7 |
| pc28-5 | PC蛋蛋 | 5 分钟 | g1 | 2,5,8 |

- 分钟场以每天 `00:00` 为锚点，例如 10 分钟场为 `00:00、00:10、00:20…`，3 分钟场为 `00:00、00:03、00:06…`。
- 号码源已在当天00:00预生成，业务后端在对应分钟第 **05 秒**起发布；05秒前不写入公开开奖记录，也不推进该期发布游标。21:30日场来源时间为 `21:30:01+08:00`，业务开奖时间为 `21:30:05+08:00`；实际发布受调度影响，`published_at` 单独记录。
- 所有场次在开奖整分之前10秒封盘，在该分钟05秒开奖后开启下一期；例如12:00:50封盘、12:01:05开奖，15秒内两面/常规及旧版选号接口均拒绝新订单。六合彩为21:29:50封盘、21:30:05开奖。
- PK10 保留数值型 `numbers`，展示用 `display_numbers` 为 `01`～`10`。
- 快3取新增 g8，每个点数 **1–6**，可重复。三个场次继续使用原位置映射。
- PC蛋蛋返回三个号码及 `sum`，前端展示 `a + b + c = sum`；和值为 0–27。
- g7 为 1–49 全量不重复排列，取前七个：前六位正码，第七位特别号；单式选号选六个不重复号码。

六合彩的选号与六正一特结构参考 [香港赛马会选号规则](https://special.hkjc.com/e-win/en-US/betting-info/marksix/types-of-entry/) 和 [奖项匹配规则](https://special.hkjc.com/e-win/en-US/betting-info/marksix/prize-qualification/)。**“澳门六合彩”名称与每日21:30时间是本项目自定义规则，不代表官方开奖源。** 当前支持正码/特码定位数字及大小单双自动赔率结算；保留六号单式的人工结算。不包含复式/胆拖组合计算。

## 启动

先启动同级 `game-api` 服务，再在当前目录运行：

```sh
go run ./cmd/server
```

| 环境变量 | 默认值 |
| --- | --- |
| BACKEND_ADDR | 127.0.0.1:8082 |
| BACKEND_DB | data/games.db |
| GAME_API_URL | http://127.0.0.1:8081 |
| GAME_API_TOKEN | 可选；显式环境密钥优先 |
| GAME_API_TOKEN_FILE | ../game-api/data/source-api.token；与号码源共用，未提供密钥时启动失败 |

8082 用于避开本机已有的 8080 服务。前端开发和 preview 已设置 `/api` 代理至 8082。生产静态托管也需要配置相同的 `/api` 反向代理；浏览器不应直接访问号码源或持有号码源 Token。

## 调用接口

成功响应为 `{ "data": ... }`，失败为 `{ "error": {"code": "...", "message": "..."} }`。

| 方法 | 路径 | 返回 |
| --- | --- | --- |
| GET | `/api/v1/games` | 全部 10 个场次配置 |
| GET | `/api/v1/sessions/{session}/state` | 最近一期、服务器时间、应开奖期号、等待状态、下期开奖时间 |
| GET | `/api/v1/sessions/{session}/draws?limit=100` | 历史倒序，默认20，最大100 |
| GET | `/api/v1/sessions/{session}/draws?limit=20&before={issue}` | 分页；before 不包含自身 |
| GET | `/api/v1/sessions/{session}/draws/{issue}` | 精确期号查询 |
| GET | `/healthz` | 业务后端进程状态 |

```sh
curl http://127.0.0.1:8082/api/v1/games
curl http://127.0.0.1:8082/api/v1/sessions/ffc-3/state
curl 'http://127.0.0.1:8082/api/v1/sessions/pc28-5/draws?limit=100'
curl http://127.0.0.1:8082/api/v1/sessions/lhc-daily/state
```

开奖记录字段：

- `session_id`、`issue`：场次与期号（北京时间 YYYYMMDDHHmm）。
- `source_issue`、`source_group`、`positions`：来源期号、组别、选位。
- `numbers`、`display_numbers`：原始数字与展示字符串。
- `sum`：快3 / PC蛋蛋和值。
- `draw_at`：业务开奖计划时间（对应分钟05秒；升级前历史保留01秒）；`published_at`：此记录实际写入业务服务的时间。
- `origin`：`simulated_history` 或 `scheduled`，前端明确区分。

`state.pending` 表示应开奖期号尚未发布。号码源离线时，已缓存批次仍按时发布；未缓存期次保留等待状态，不在前端或业务后端临时造数。缺期不会自动用上一期替代。`next_draw_at` 始终为下一个05秒开奖时间；`bet_close_at` 是本期封盘时间，比其早15秒；`betting_open` 表示当前时刻是否处于允许下注的时段（仍需检查场次开关和账户）。跨过整分但未到05秒，不会切换下注期号。`expected_issue` 表示当前应有的上一期开奖。

机器可读定义：`docs/openapi.json`。

## 初始历史与后续持久化

1. 首次启动为**每个场次**初始化 100 期，共 1000 条模拟历史。每天一期的六合彩对应过去100个已到期的21:30时刻。
2. 仅初始化过去的周期，排除启动所在分钟，避免与正在生成的号码源冲突。
3. 同一模拟来源期号的号码只生成一次，各场次复用这些号码后取位，保持相互映射一致。
4. 模拟来源存放在业务数据库独立的 `seed_sources_v1` 中，**不会写入或修改真实定时号码源数据库**；`simulated_history` 的来源期号属于此模拟命名空间。
5. 初始化标记、场次历史持久化，刷新和重启不会重新生成。此后总记录会随新期开奖超过100，前端显示最近100期；HTTP接口可继续分页查询旧期。
6. 业务后端独立线程预取号码源全部新批次，缓存到 `private_source_cache_v1`。发布线程每100ms检查到期批次，发布游标和对应场次结果在同一事务写入。网络超时不阻塞发布；缓存重启保留。缺期不换号、不临时造数。
7. 号码源 schema_version=5 为每天预生成的十一组，兼容 schema4 八组及1/2/3旧六/七/八组。g9/g10/g11 新增为独立1–49排列，现有10个场次映射不变。旧期不伪造缺失组；没有 g7/g8 的来源不发布相应日场/快3。
8. 快3改用 g8 后使用新的 `k3-*:g8` 历史存储，每场初始化100期1–6模拟历史；旧g3快3记录留在原数据库命名空间，当前接口不混入旧记录。同一期模拟来源新增g8时保留原有组，不重抽。

## 账户与运营模块

已增加登录注册、持久化余额与流水、三级邀请佣金、资金申请审核、订单扣款、锁定赔率及自动结算、管理员用户列表与玩法设置。详细接口见 [账户与三级邀请 API](docs/accounts-api.md)。

前端管理入口 `/f7cc4f635d178admin`；初始管理员凭证在首次启动时生成至 `data/admin-bootstrap.txt`（或由 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 指定）。账户数据库 `ACCOUNTS_DB` 默认 `data/accounts.db`，与原开奖数据独立。

后台随机试算需“确认采用”才会改变该场次本期结果。前端在开奖上一分钟59秒禁用随机和采用，后端在开奖分钟00秒起拒绝操作，并在等待数据库写锁后、提交前再次校验时间。例如21:30:05开奖，前端21:29:59截止，后端21:30:00截止。已通过校验的事务若因落盘延迟跨过00秒，赔付预计算会等待采用提交完成后读取号码。正式公布后，如果未入账的预计算与公开结果不一致，会在订单快照未变化的前提下，按公开结果重新计算并与入账一起原子保存，记录 `order.payout_recalculate` 审计；已结算、已退款订单不会重复处理。

佣金初始三级比例均为0，后台配置后对新订单生效。A→B→C→D 中 C 同时是被邀请人与邀请人；D 的已结算有效投注分别向 C/B/A 计佣。支付通道未接入，资金申请仍需人工核对。两面/常规新订单在开奖整分后00.010秒开始一次性预计算整期订单，目标05秒内完成，公布结果并通过校验后一次事务入账；延迟时继续重试；同一用户同一期跨场次订单一起处理，不再按人数分批。预计算与进度持久化，重启继续，失败用户单独重试。旧版订单与六号单式保留人工结算。玩法和赔率接口见 [赔率与自动结算](docs/markets-api.md)。
