# 账户、钱包与三级邀请 API

业务服务 `http://127.0.0.1:8082`；浏览器通过前端同源 `/api` 代理访问。成功为 `{ "data": ... }`，失败为 `{ "error": { "message": "..." } }`。所有金额使用**整数分**，比例使用基点（100 = 1%）。不允许浏览器自行指定用户 ID、角色、账户余额或上级链。

## 登录与部署

- 账户数据库独立保存在 `data/accounts.db`，开奖数据库仍为 `data/games.db`。bbolt 适用于当前单实例部署；数据库目录需持久化。
- 首次启动读取 `ADMIN_USERNAME`（默认 `admin`）、`ADMIN_PASSWORD`。未配置密码时由12字节加密随机数生成16位URL安全密码，保存到 `data/admin-bootstrap.txt`（0600 权限）。已有管理员时不会创建新管理员，也不会通过环境变量覆盖已有密码。
- 登录 Cookie：`starlight_session`，HttpOnly、SameSite=Strict、7 天有效。数据库只保存令牌摘要；密码使用独立随机盐的 PBKDF2-HMAC-SHA256（600,000 次）。改密/停用会撤销现有会话。
- 部署 HTTPS 时配置 `COOKIE_SECURE=true`；业务 API 不开放跨域。所有写请求要求 `Content-Type: application/json`，浏览器 Origin 必须与 Host 一致。反向代理需保留原始 Host（例如 nginx `proxy_set_header Host $http_host;`）。开发和预览代理已设置 `changeOrigin: false`。
- 登录、注册、改密各按服务看到的来源 IP 限制每分钟15次。当前开发代理的用户共用代理 IP；大规模部署需加入受信任代理的客户端 IP 策略。
- 新账户按 `registration_bonus_cents` 配置赠送测试余额（整数分，默认0）；账户创建、赠送流水和登录会话在同一事务提交。旧 localStorage 模拟积分/订单不迁入账户资金。

## 会话与账户

| 方法 | 路径（均以 `/api/v1` 开头） | 请求 / 说明 |
| --- | --- | --- |
| GET | `/site` | 公开公告、注册开关、邀请码必填开关、10个场次设置、三级佣金比例 |
| POST | `/auth/register` | `username`, `password`, `phone`（必填手机号）, `name`（选填姓名）, `invite_code`（`invite_required` 开启时必填，否则选填）；成功自动登录 |
| POST | `/auth/login` | `username`, `password` |
| POST | `/auth/logout` | `{}`；清除当前会话 |
| GET | `/auth/me` | 当前用户、角色、余额、冻结金额、邀请码、邀请人 ID |
| POST | `/auth/password` | `old_password`, `new_password`；新密码8–16位，原密码兼容旧长度；成功后重新登录 |
| GET | `/orders?page=1` | 当前用户的全部历史订单，按新到旧分页；每页10条，返回 `items`、`total`、`page`、`page_size`；超出末页时返回末页 |
| GET | `/account` | 当前用户、邀请人信息、余额流水、资金申请、订单、佣金、三级团队人数和成员 |

会员投注记录支持 `GET /orders?page=1&status=&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`。日期按**北京时间的投注创建日期**筛选，与既有 `status`（空、`pending`、`win`、`lose`、`push`、`refunded`）叠加；开始/结束日均可省略或为空，包含开始日零点和结束日全天（下一日零点不包含），不使用结算日期或服务器本地时区。任一日期条件非空时排除没有创建时间的历史记录，无日期条件时继续保留。非空日期必须严格为有效的 `YYYY-MM-DD`（年份0001–9999，校验闰年），开始日晚于结束日返回400及 `error.message`。服务端只读取当前登录用户的完整历史，先应用状态与日期条件，再计算 `total`、`total_stake_cents`、`total_payout_cents` 和每页10条的分页；汇总不受当前页或最近200条限制，撤销退款不计派彩。前端日期点击“应用”后生效并回到第一页，“清除日期”保留状态条件；轮询和翻页保留已应用日期，切账号清空筛选及旧数据。此筛选仅适用于会员订单查询，不扩展后台接口。

用户名为4–32位字母/数字/下划线（不区分大小写），新设置的登录密码长度8–16字节（注册、个人改密、后台重置及首次管理员初始化）；注册与后台重置仍需同时包含大小写字母。验证既有登录密码或原密码时保留原128字节上限，不强制修改旧长密码；提现密码仍为6位数字。手机号支持中国大陆11位手机号或以 `+` 开头的国际号码（7–15位数字），姓名最多40个字符，不允许控制字符；两者会去除首尾空白。手机号必填仅用于新注册，已有账户仍可正常登录。联系方式仅返回本人和管理员，团队成员列表不包含这些资料。账户概览列表保留最近200条；订单页面通过 `/orders` 分页读取完整历史，每页10条。后台订单管理每页10条，其余后台列表每页20条；响应页码以服务端返回的 `page` 为准。

会员「交易记录」通过 `/account/transactions?page=1` 读取本人完整充值、提现申请，包含待审核、通过、驳回状态，每页10条。服务端先按本人及 `kind=deposit/withdraw` 筛选，再计算总数和分页；其他申请类型不进入交易记录，原始记录不删除。页面标题统一显示“充值”“提现”。

## 进入游戏的二级密码

个人中心提供独立的「二级密码」设置与开启/关闭开关，与登录密码及6位提现密码互不影响。旧账户默认未设置、未开启，不批量更改现有账户。

| 方法 | 路径（以 `/api/v1` 开头） | 请求 / 说明 |
| --- | --- | --- |
| GET | `/auth/secondary-password/status` | 当前登录会话的 `is_set`、`enabled`、`verification_required`、可选 `verified_until` 及 `server_time` |
| POST | `/auth/secondary-password` | `new_password`、`confirm_password`；首次设置需 `login_password`，以后修改需 `current_password`。首次设置成功自动开启；修改已关闭的密码不会自动开启 |
| POST | `/auth/secondary-password/toggle` | `password`（当前二级密码）、`enabled`（必传布尔）；保留密码，切换后所有旧游戏验证失效 |
| POST | `/auth/secondary-password/verify` | `password`；成功只授权当前登录会话，返回最新状态 |

新设或修改后的二级密码为1–8个Unicode codepoints，不强制大小写组合，可用纯数字、全大写或全小写；密码比较本身区分大小写，不裁剪首尾空格。验证、开关及修改时的当前密码允许1–12个Unicode codepoints，以兼容已存在的旧9–12字符密码；不截断或重置存量密码，新密码及确认密码严格限制为1–8个。前端按codepoints校验，输入框的HTML `maxlength` 按UTF-16码元设置：新密码及确认密码16，当前密码及验证密码24。后端使用独立随机盐及PBKDF2-HMAC-SHA256（600,000次）存储，不返回原文、摘要或盐。`User`仅新增 `secondary_password_set` / `secondary_password_enabled` 布尔标志。

开启后每次登录首次进入游戏都需验证，同一次登录内各游戏共用时效。每次成功验证的期限固定为以下最早时刻：验证后1小时、北京时间次日00:00、登录会话到期；浏览、刷新和后台轮询不续期。退出后该会话的验证一并删除，新登录或其他设备不能继承。修改二级密码或切换开关会改变配置修订号，使所有旧验证失效但不退出登录。

游戏入口在服务端状态检查通过后才显示。停留在游戏中时，时限到达也会隐藏游戏并提示再次验证；保留已挂载的投注组件和幂等编号，验证不会自动重投。后台另在三种下单路径（单式、单选、批量）的同一数据库事务中核对Cookie对应的登录会话及验证期限，不能凭前端开关、客户端时间、其他用户令牌或直接请求绕过。未验证返回403及错误码 `SECONDARY_PASSWORD_REQUIRED`，不清除登录；账户中心、记录和关闭二级保护的账户不受影响。

验证、修改及开关共享每账户15分钟最多5次密码检查，重启或切换设备不能绕过；成功后清除计数，超限返回429及 `SECONDARY_PASSWORD_RATE_LIMITED`。所有接口均需登录、同源写请求及JSON，状态不缓存。未增加管理员绕过、代设或自动重置入口。

发布时需同步更新前后端，已开启保护的会员若使用旧缓存页面，下单会被服务端拒绝，需刷新后完成验证。上线后若已有会员设置或开启二级密码，不得直接回退不认识该保护的旧后端，否则会绕过保护或在写用户记录时丢失新字段；也不能恢复旧数据库覆盖后续账户及订单。应保留二级密码字段和验证逻辑向前修复。

## 三级关系与佣金

### 管理员代理关系图

`GET /api/v1/admin/agents` 为只读管理员接口，普通会员403、未登录401，响应不缓存。可选 `username` 为完整账号（忽略大小写、精确匹配），返回该账号作为根；`parent_id` 返回该账号的直属下级，两者不可同时指定。均为空时返回无上级或上级缺失的顶层账号，包含管理员以便完整追溯邀请树。`page` 从1开始，每页20项，超末页返回末页。

返回 `{data:{items,total,page,page_size,parent?}}`；查询子级时额外返回parent节点。每个节点包含ID、用户名、姓名、角色、状态、注册时间、上级ID/用户名、上级缺失标志、`deposit_cents`个人累计充值、`direct_count`直属人数、`team_count`全部下级人数、`team_deposit_cents`全部下级累计充值（不含本人）。不返回联系方式、登录/提现/二级密码、哈希、盐或会话数据。

团队统计覆盖全部层级，包含已停用成员，不受佣金三级限制。充值使用历史正数入账流水，已审核充值及后台充值计入，明确标注“充值”的旧调账按既有分类兼容；奖励、待审核/驳回申请不计入，不以当前余额或打码量代替，不抵扣管理扣减、不随提现归零。遍历叶到根聚合以免多层重复累计，检测到循环关系直接报错，不静默截断或修改数据。

卡片默认紧凑，仅保留用户名、上级、个人累计充值、直属/全部下级、下级累计充值五项。顶部 `day`（北京时间日期）与 `today_stake_cents` 为当前查询范围含根账号的今日未撤销投注总额，不受分页限制；节点 `today_stake_cents` 为本人，`team_today_stake_cents` 为全部下级，含待开奖和已结算订单，退单不计。统计按当前归属查询；日期跨北京时间零点，不使用浏览器时区或订单结算时间。

「全屏查看」将当前关系图移动到全屏弹窗，不重新查询或清空已展开分支；保留搜索、逐层展开和分页。关闭按钮或Esc退出，限制Tab焦点在弹窗内，关闭/卸载恢复页面滚动；全屏内关系图独立滚动。

### 管理员更改会员上级

「用户列表 → 更改上级」支持迁移会员及其整支下级：`GET /admin/users/{id}/inviter` 读取当前上级，`POST /admin/users/{id}/inviter/preview` 预览（`inviter_username` 为完整账号；或明确 `detach:true` 设为无上级），返回新旧上级、下级人数及关系 `revision`；`POST /admin/users/{id}/inviter` 再提交原候选、revision、2–500字原因和幂等key确认变更。

仅管理员可操作会员，不可更改管理员上级；不能指向自己、自己的任何层级下级、已停用或不存在的账号。预览覆盖全体关系和状态，不含余额或密码；提交时在同一写事务内再次核验，拒绝过期预览或循环关系，原key精确重试不重复操作。只修改目标会员的上级ID，后代直属关系保持，团队人数、充值与今日流水即时按新关系重算；会员侧团队总览下次刷新/15秒轮询同步。历史订单、已锁定的上级与佣金比例、已生成佣金、余额、密码及会话不改，旧订单按旧快照结算，新订单使用新关系。日志记录前后上级、分支人数和原因。预览本身不落库。

后台「代理关系」按层懒加载，支持查找根账号、切换到上级或任意节点为根、展开/收起、每层加载更多、刷新及紧凑显示。关系图内滚动，不提供改绑邀请关系或调整资金的操作。

每个用户保存一位 `inviter_id` 和自己的 `invite_code`，两个字段可以同时存在。邀请关系仅在注册时绑定，后续没有改绑接口。

例如 A → B → C → D：C 既被 B 邀请，也邀请 D。D 的有效订单给 C 一级佣金、B 二级佣金、A 三级佣金；A 的上级不会收到该订单佣金。团队人数也只统计向下三级。

- 三级比例 `commission_bps: [500, 200, 100]` 表示5%、2%、1%，每级可独立设为0，合计最多100%。**初始值为 `[0,0,0]`**，需管理员自行配置。
- 下单时保存 `ancestors`、`commission_bps`，修改设置不追溯已提交订单。
- 有效投注 = 已结算（自动或人工）、未撤销且非和局退本的订单金额；不能对待开奖订单提前结算。人工结算端必须查到对应的 `scheduled` 开奖记录，模拟历史不作为可结算来源。
- 单级佣金 = `cost_cents × rate_bps / 10000`，向下取整到分。结算与最多三笔佣金在同一事务提交；已处理订单不可再次结算。
- 佣金状态为 `available` / `claimed`。`POST /commissions/claim`（`{}`）一次领取当前全部可用佣金到余额，佣金状态与余额流水原子更新。

## 钱包与订单

### 保存提现地址与充值二维码

当前会员页面的充值、提现均只保留USDT；后台充值二维码仅展示USDT配置。新 `/wallet/requests` 不接受人工存/提款，已受理的旧人工申请仍可用原key和原内容重试、查看与审核，不新增或改写旧单。旧人工收款二维码字段保留存储兼容，不向会员接口返回，不在前台提供人工通道。

会员可通过 `GET /wallet/withdrawal-addresses` 读取本人TRC20/ERC20地址，通过 `PUT /wallet/withdrawal-addresses/{network}` 保存或更改，正文为 `{ "version": 0, "address": "完整地址" }`。首次版本为0，更新时使用读取到的版本；旧版本不能覆盖不同的新地址，同地址重试不重复写入。地址在服务端按会员与网络分别保存，换设备登录仍可读取，不写浏览器持久存储。接口只认登录会话中的本人身份，不接受指定其他会员；停用账号不可读写。修改偏好不改变余额、凭据或任何已提交申请，提现仍须逐笔通过提现密码验证，申请锁定独立的收款地址快照。

后台「收款设置」支持 `qr_code_data_url`（USDT充值二维码）；旧 `manual_qr_code_data_url` 仅保留存储兼容，使用原 `GET / PUT /admin/payment-settings` 的版本检查。仅接受内嵌PNG/JPEG、每张最多256KiB、宽高64–2048像素，后端检查实际图片内容，拒绝SVG、远程图片链接、损坏或超限图片。该管理PUT专用正文上限768KiB，其他JSON接口仍为128KiB；前端选择图片后，需点击保存设置才生效，支持预览、更换和移除，日志只保存图片哈希而非整张图片。

会员登录后通过 `/wallet/payment-settings` 读取图片：仅在USDT通道可用时展示USDT二维码，旧人工二维码不返回；空图片不显示，不预设任何真实收款二维码。客户端“在线支付”将此二维码放在收款文字信息上方；“USDT账户”仅显示收款文字和填写表单，不展示二维码。两个选项共用当前USDT配置、完整交易ID校验及申请流程，切换保留输入内容，待确认申请期间禁止切换。更改USDT收款网络或地址需清除/重新上传对应二维码，避免沿用旧地址图片；管理员必须核对二维码内容与实际收款账户/地址一致，系统不会自动识别图片中的收款地址。已有资金申请快照不因更换二维码改变，也不会自动审核或发起转账。

USDT充值必须填写完整交易哈希：TRC20为64位十六进制字符，ERC20为0x开头的66位哈希，规范化为小写并按网络与完整哈希防重复提交。新申请拒绝仅5位后缀。历史已接受的后5位申请仍可使用原幂等key重试与人工审核；历史索引继续绑定申请ID，不改写已有申请或资金记录，不能仅凭后缀批准。

管理员 `POST /admin/users/{id}/wagering` 接受可选的 `required_cents`、`turnover_cents`（整数分，0–100000000000）；省略金额保持原值。`green_channel` 沿用布尔设置，前端始终提交当前开关值；`version`、`revision`、2–500字原因 `note` 和幂等 `key` 必填。显式 `turnover_cents:0` 自动清零打码量；同时传正数 `required_cents` 会拒绝。只传 `required_cents` 可在流水仍为0时独立设置打码量。界面“清零两项”仅预填数值，点击保存才生效。

两项调整记录保存在原打码调整桶，记录当时入账与订单边界，按边界顺序重算并在每个调整点将负值归0，之后新记录继续累计。提现仍只消耗提交时覆盖的记录和调整；后续调整、清零及新记录不会被旧提现吞掉，也不会绕过旧申请因撤单导致的门槛复核。调整使用版本/修订号防并发覆盖，原key精确重试不重复应用，日志保存前后值及原因；不修改余额、原入账/订单、累计充值历史或新建数据桶。部署后不得回退到忽略新打码量调整字段的旧业务程序，亦不得恢复旧数据库覆盖新交易。

打码量（`required_cents`）由本轮累计到账充值＋奖励构成，并可由管理员独立修改；每次新增到账仍继续叠加。打码流水（`turnover_cents`）＝本轮未撤销累计投注金额＋后台流水调整。管理员明确将打码流水设为0时，同时将打码量清零；自然处于0流水或未修改流水时，不自动清除新充值或独立设置的打码量。原始充值、奖励、投注和余额不受打码调整影响。本轮内充值与未撤销下注累计叠加；充值审核不修改打码统计截止点。正数后台充值`admin_deposit`及奖励`admin_reward`分别计入充值/奖励打码量，修复后台充值被遗漏、仅显示后续审核充值的问题；未分类管理调账不冒充充值或提现。提现门槛为打码流水≥打码量，相等也允许（例如600元≥600元）；绿色通道沿用既有豁免。提现以提交申请时保存的统计截止点为准，审核通过才将申请覆盖的打码量与打码流水清零；提交后的充值、奖励、投注及两项后台调整继续累积，保留到下一轮。提交申请和驳回均不清零。旧记录按现有分类重新计算，不手工改写余额或流水，不改变提现重置规则；上线后历史后台充值和奖励可能提高本轮打码量，不能以旧服务端回退绕过新门槛。

| 方法 | 路径 | 请求字段 |
| --- | --- | --- |
| POST | `/wallet/requests` | `kind`: `deposit` / `withdraw`, `amount_cents`, `note`, `key` |
| POST | `/orders` | `session_id`, `issue`, `numbers`, `amount_cents`（或旧版 `multiplier`）, `unit_cents`, `key` |
| POST | `/commissions/claim` | `{}` |

`key` 为16–100字符的随机幂等编号，一次逻辑操作对应一个编号，网络失败可以用**同编号与同请求内容**重试；同编号用于不同内容会拒绝。号码、期号、单价、倍数、玩法启用状态、封盘时间及余额均由服务端检查。`unit_cents` 为用户当前确认的单注价格，必须与服务端配置相同，防止设置变更后以未确认的新价格扣款。

```json
{
  "session_id": "ffc-1",
  "issue": "202610112101",
  "numbers": [1, 2, 3, 4, 5],
  "multiplier": 1,
  "unit_cents": 200,
  "key": "replace-with-a-new-random-id"
}
```

示例期号仅为格式示意，实际值需读取场次状态 `next_draw_at` 并转换为北京时间 `YYYYMMDDHHmm`。

充值申请不会自动入账，管理员核对外部到账后审核通过才加款。提现提交时冻结余额，驳回解冻，通过后消除冻结；系统本身不会向银行或支付机构转账。单次资金申请范围100–100,000,000分。

## 管理接口

### 删除与恢复会员

用户列表增加“删除用户”和“已删除”入口。删除只标记会员 `deleted:true` 并设为停用，撤销该会员全部登录及临时登录挑战，邀请码停止新注册；不删除凭据、用户名/邀请码索引、订单、账变、资金申请、佣金、操作日志或下级关系，也不删除或迁移下级。账号名称保留，不能被重新注册。关系图保留该节点并显示“已删除”，图接口的节点 `status` 投影为 `deleted`，历史团队统计继续保留该节点及其后代。

- `GET /admin/users/{id}/deletion`：管理员读取单次操作预览，返回 `username`、不透明 `revision`、`deleted`、`balance_cents`、`frozen_cents`、`betting_frozen_cents`、`available_commission_cents`、`pending_requests`、`pending_orders`、`direct_count`、`can_delete` 和 `blockers`。预览只读、不缓存，不返回凭据或内部删除修订号。
- `DELETE /admin/users/{id}`：JSON正文 `{revision,confirm_username,note,key}`。需确认完整账号、2–500字原因及16–100字符幂等key。余额/提现冻结不为0、存在未结算投注（即使本金为0）、待处理资金申请或未领取正数佣金时拒绝删除。管理员及当前登录账户不可作为目标。
- `GET /admin/users`：默认只含未删除账号（含停用会员）；`GET /admin/deleted-users`：只含已删除账号，沿用 `q` 查询及每页20条分页，筛选在总数/分页之前。运营概览的账户总数和历史统计仍包含保留的归档账号，避免破坏历史财务对账。
- `POST /admin/users/{id}/restore`：同一正文结构，需新的预览与key；只恢复已删除会员，结果为 `deleted:false,status:disabled`，仍需在用户列表明确启用后才能登录。恢复不会复活旧登录会话，也不改凭据、财务或邀请关系。即使原订单后续产生佣金等删除阻止条件，仍可恢复账号处理。

所有操作在写事务内重新检查管理员权限、目标身份、预览修订及当前资金/待办状态。删除/恢复循环会更新私有修订，旧预览不能再次生效；同key同内容精确重试只返回原确认，不会重新删除已恢复账号，同key更改内容拒绝。日志记录前后状态、账号、直属人数及原因。已删除账号不能通过普通状态切换、改密、改上级、调余额或打码设置绕过恢复；已受理余额/打码调整的原key重试保持幂等。部署后不能回退到忽略删除标志的旧业务程序，不能用旧数据库覆盖上线后交易。

### 代理关系完整导出

`GET /api/v1/admin/agents/export?format=xlsx|data&username=<完整账号>`，仅有效管理员会话可访问，所有响应 `Cache-Control: no-store`。`username` 去除首尾空白并忽略大小写精确匹配，空值导出全部顶层账号及所有后代（含管理员、禁用账号与孤儿根）；指定账号导出本人及所有后代。无深度、分页或展开状态限制，父节点先于子节点，每个节点一次。孤儿保留原上级ID并标记 `missing_parent`；任意环路导致整次失败。

- `format=xlsx`：200返回标准 `.xlsx` 附件 `agent-relations-YYYYMMDD-HHMMSS.xlsx`（北京时间），MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。用户名与上级使用文本单元格，保留前导0且不执行公式；金额从分转换为元，以数值保存并显示两位小数；冻结首行并启用筛选，表头粗体浅色填充、设置列宽。列为用户名、上级、状态、直属下级(人)、全部下级(人)、个人累计充值(元)、下级累计充值(元)、个人今日流水(元)、下级今日流水(元)。状态显示正常/已停用，缺失上级显示记录缺失。第二张“导出说明”表包含统计日期、导出时间、scope、今日总流水（含本人，数值元）和下级不含本人的口径说明；总流水不逐行累加团队金额。最多1048575个账号加一行表头，节点金额及总流水范围0–999999999999999分；超过范围返回400 JSON，不截断、不输出部分文件。
- `format=data`：200返回 `{ "data": { "items": [], "day": "2026-10-25", "today_stake_cents": 0, "exported_at": "2026-10-25T12:00:00+08:00", "scope": "" } }`。`scope` 为去空白后的查询账号（保留查询大小写）或空字符串；`exported_at` 为北京时间RFC3339。前端使用完整数据生成SVG/PNG，后端不接受 `format=svg/png`。

`items` 节点只包含 `id`、`username`、`inviter_id`、`inviter_username`、`status`、`missing_parent`、`direct_count`、`team_count`、`deposit_cents`、`team_deposit_cents`、`today_stake_cents`、`team_today_stake_cents`，不返回姓名、手机号、密码摘要等资料。上级在导出范围之外时仍保留真实上级ID，前端将范围内没有父节点的账号作为图根。空集合返回 `items:[]`。

节点及统计复用代理树聚合，从单个bbolt只读快照读取全部用户、充值流水、订单；团队统计只包含后代，不含本人。顶层 `today_stake_cents` 汇总范围内本人及后代，不重复计算。今日按北京时间自然日统计 pending/settled 订单本金，排除 refunded；充值沿用现有充值分类和历史兼容口径，不包含奖励或负充值。

`format` 必填且仅接受 `xlsx` / `data`；非空 `parent_id` 或 `page`、重复的已知查询参数均返回400。未登录/失效会话401、普通会员或禁用账号403、账号不存在404；参数、环路、Excel范围错误400。错误统一 `{ "error": { "message": "..." } }` JSON，无附件头。导出只读，不修改统计、订单、审计或生产数据库。

全部要求管理员会话，权限在后端验证。前端入口 `/admin`。

### 邀请码注册限制

后台「玩法与分销 → 站点设置」新增“注册必须填写邀请码”。配置字段为 `invite_required`（布尔值），默认 `false`，旧数据库缺少此字段时保持可直接注册。管理员通过 `PUT /api/v1/admin/settings` 保存完整设置，公开 `/api/v1/site` 返回该字段供注册表单标记必填。

注册事务内读取最新开关：开启时拒绝缺失或纯空白邀请码；填写的邀请码始终需要有效且邀请人处于正常状态。关闭注册优先于邀请码开关；修改不改变现有邀请关系，不影响已有用户登录。保存与现有站点设置共用权限检查和审计日志。

### 注册赠送测试余额

后台「玩法与分销 → 站点设置」的“新用户注册赠送金额（元）”对应 `registration_bonus_cents`，范围0至100000000分；10000元对应1000000分。设为0即关闭，已存在账户不补发。底层默认0，当前开发环境可由管理员配置10000元。只在注册成功时赠送一次；失败、重复用户名或登录不赠送；流水类型 `registration_bonus`，备注“注册赠送（开发测试）”。赠送本身不产生佣金。完整设置接口、权限与审计沿用现有逻辑。

### 游戏控制统计

`GET /api/v1/admin/game-control` 仅管理员可用。返回 `today`、`yesterday`、`month` 盈亏区间和明细，`pending_amount_cents` / `pending_orders` 是所有待结算订单本金及注数（包含旧版人工结算），`sessions` 展示各场次今日盈亏、待结算金额、接单状态和固定取号来源。所有金额为整数分，统计从单个数据库只读快照读取。

期间按北京时间自然日/月，以订单 `settled_at` 归属；`gross_profit_cents = stake_cents - payout_cents`，`net_profit_cents = gross_profit_cents - commission_cents`。佣金按所属订单归期，包含已领取与未领取金额。退款订单排除，和局退本净额为0，待结算订单不计入利润。缺少结算时间的旧单通过 `undated_settled_orders` 单独提示，不猜测归期。充值/提现/调账/注册赠送不计入投注盈亏；测试余额投注计入，统计不是现金利润。前端每15秒刷新，接口错误保留并标注上次统计时间。

当前为单实例只读聚合；订单和佣金量增大时应增加事务内维护的日期汇总表以避免全表读取。不修改开奖、取号、订单赔率快照或结算事务；不提供按照押注挑选结果的控制接口。

### 单用户单期投注上限

每个场次的 `plays[].user_issue_limit_cents` 默认 **2000000分（20000元）**，可在后台「玩法与分销 → 玩法与场次」按场次调整。取值不低于起投金额，最高100000000分（100万元）。这是同一用户、同一场次、同一期所有投注本金之和，两面、常规和旧版单式共享额度；不同用户、场次和期号相互独立。

两个下单接口在同一写事务中完成幂等检查、额度预占、扣款和订单保存。使用持久化 `user_issue_stakes` 累计索引，避免逐次下注扫描订单；并发请求串行检查可用额度。扣款或其他步骤失败会一起回滚。重复请求返回原订单，不重复占额度。管理员撤销退款在同一事务释放本金额度；正常结算（包括和局退本）不释放已接受投注累计。调低限额不撤销已接订单，已有累计超限时拒绝新增订单。

首次升级按已有 pending/settled 订单重建索引，排除 refunded；此后重启保留累计，缺少配置的旧场次初始化为20000元。游戏控制列表展示上限；用户超限时返回本期剩余额度，不修改余额。


### 游戏控制：下期号码与预计盈亏

`GET /api/v1/admin/game-control` 仅管理员可访问。每个 `sessions` 场次新增 `latest`（上期已发布结果）、`next`（按期号与位置从私有预生成缓存提取的下期结果）、`next_issue`、`next_draw_at` 与 `next_estimate`。缺少预生成来源时 `next` 为 `null`，包括跨日后尚未生成或同步的号码；读取不会生成、发布号码或结算订单。公开场次状态与历史接口不包含预生成结果。

`next_estimate` 包含 `orders`、`stake_cents`、`payout_cents`、`commission_cents`、`net_profit_cents` 与 `unresolved_orders`。只统计对应 `next_issue` 的待结算订单，按订单锁定的规则、赔率、祖先链和佣金比例预估；派彩与佣金逐单按分取整，和局退本不计佣金。净盈亏＝投注金额－派彩（含本金）－佣金。缺少下期号码或存在无法自动判定的订单时净盈亏为 `null`，避免把部分预估误作全部盈亏。预估不计入今日/昨日/本月已结算盈亏。管理页面每5秒同步数据，倒计时按服务器时间每秒更新。


### 下一期随机试算与确认采用

管理员可调用 `POST /api/v1/admin/game-control/{session}/preview`，提交 `issue`、可选 `candidate_id` 和 `random`。`random:false` 读取当前号码及候选号码的最新盈亏；`random:true` 按场次号码范围及是否允许重复生成随机候选。候选保存在私有存储，不改变实际结果。两组盈亏以同一个订单快照计算。返回 `current`、`candidate`、`current_estimate`、`candidate_estimate`、`cutoff_at`、`server_time`。弹窗每2秒重新试算。

`POST /api/v1/admin/game-control/{session}/apply` 提交 `issue` 和 `candidate_id` 后采用候选，只影响该场次该期，不修改共享源组或其他场次。后端只接受服务端生成且版本未过期的候选；重复提交或另一管理员已经改号时拒绝覆盖。号码版本与包含操作者、时间、前后号码的记录一起原子保存至号码库的私有存储，重启后继续有效。

**截止时间为开奖所在分钟00秒**：21:30:05开奖时可操作至21:29:59，21:30:00起禁止打开试算、随机及确认采用，统一提示“已超过开奖时间不可修改”。后端取得写锁后采样时间，并在提交前再次校验；旧期弹窗不会自动变成下一期。00秒赔付预计算与05秒公开结果都读取同一份已采用号码，公开接口不会提前返回号码。次日来源尚未生成/同步时不能凭空生成可采用结果。

管理员批量试算使用 `POST /api/v1/admin/game-control/{session}/preview-batch`：发送 `issue`、`count:1` 或 `count:5` 一次生成候选；发送 `count:0` 和 `candidate_ids` 刷新原有候选，空数组只读取当前号码。返回 `current`、`current_estimate`、`candidates:[{candidate,estimate}]`、`cutoff_at` 和 `server_time`。同一批比较期间禁止采用新号码，所有候选及当前号码的盈亏基于同一份订单快照；旧版本候选整体拒绝刷新或采用。权限和截止规则与单组接口一致。

## 用户状态（管理员）

入口位于“游戏控制”内、“场次状态与号码来源”卡片下方。手动或随机采用号码后，两张卡片立即重新读取号码及预计盈亏。

`GET /api/v1/admin/user-status?username=完整用户名`：用户名忽略大小写、精确匹配；空白或省略用户名时汇总全部用户，返回 `all_users:true`、`user:null`，包含全部游戏场次。非空用户名不存在返回404，未登录401，普通用户403。

返回用户资料、`as_of`、`summary` 和各场次 `sessions`。本期按各场次下一次开奖期号计算，只计入查询范围内（全部用户或指定用户）的本期 `pending` 订单，排除旧期、已结算、已退款及其他用户订单。`orders` 包含逐笔下注用户名、下注内容、下单赔率、金额、预计结果及派彩。页面默认展示全部游戏，清空用户名后查询可返回全部模式；单用户查询仍只展示有本期押注的场次。两种模式均每5秒更新，改号后即时刷新。

`user_profit_cents`＝预计派彩（含本金）－下注金额，正数为用户盈利，负数为用户亏损；不扣平台佣金、不含分销佣金收入。计算复用结算规则与下单快照，依据当前实际采用号码，随订单及号码变化刷新。缺少号码或需人工判定时，相应订单的预计派彩及盈亏为 `null`，汇总盈亏为 `null`，汇总派彩仅含已成功试算部分；`unresolved_orders` 表示未能试算注数。无本期押注时金额与盈亏为0。接口只读，不修改余额、订单或开奖号码。

### 手动修改当前采用号码

用户状态的 `sessions[].number_rule` 提供号码数量 `count`、范围 `min/max` 和是否允许重复 `allow_repeat`。管理员通过现有 `POST /admin/game-control/{session}/preview` 发送 `issue`、`numbers`（新号码数组）与 `expected_numbers`（打开编辑器时的原号码），生成手动候选；不能同时指定 `random` 或 `candidate_id`。缺少预生成号码、号码规则不符、原号码已改变、期号切换或达到截止时间都会拒绝。再通过现有 `/apply` 携带候选ID采用，复用版本校验、截止时间和原子修改日志。修改仅作用于目标场次本期，但影响该场次本期所有用户的结算；不会更改其他场次或公开未开奖的号码。


## 可用余额与投注冻结

`balance_cents` 是可再次下注、可申请提现的余额。下注时，在同一数据库写事务中扣减可用余额并保存待结算订单；提现申请也只从可用余额转入提现冻结，失败事务整体回滚。

`GET /account`、管理员 `/user-status` 的顶层 `betting_frozen_cents`，以及管理员用户列表每行和运营概览中的同名字段，汇总该范围全部 `pending` 订单的本金。统计覆盖跨期订单与待人工结算订单，不受最近200条展示限制；已结算、撤销订单不计入。字段由订单状态计算，不重复扣款，不迁移或重写已有余额。原 `user.frozen_cents` 及流水 `frozen_cents` 仍表示提现冻结。页面分别显示投注冻结与提现冻结。

提前试算只生成私有赔付数据，不释放资金。开奖后正式结算在同一事务中改变订单状态并入账派彩：未中奖只结束投注冻结，中奖增加含本金派彩，和局退本或撤销退回原本金。重复请求不会重复扣款、退款或派彩，服务重启后冻结统计继续以持久化订单为准。


## 资金待处理提醒

`GET /api/v1/admin/requests/pending` 仅管理员可访问，返回全部待处理充值/提现申请的 `total`、`deposit_count`、`withdraw_count`、两类 `*_amount_cents` 汇总，最新待处理编号 `latest_id` 和最多5条最新 `items`。统计不受审核列表分页、搜索条件影响，读取不会审核申请或改变资金。

管理员后台右上角每5秒查询，进入后台有待处理申请时自动展开；收起后保留待处理数量，新编号出现时重新展开，即使待处理总数未变化也会提示。每条申请可打开原审核窗口，审核成功或遇到已处理冲突后重新读取状态，全部完成后隐藏。页面恢复可见时立即更新；离开后台停止轮询。

## 多选批量投注

`POST /api/v1/market-orders/batch`：已登录用户提交 `session_id`、`issue`、`unit_cents`、`amount_cents`（每注金额）、`selections: [{market_id, odds_milli}]`、`key`。支持1–500个不同投注选项，可跨两面和常规分类；全部属于同一场次同一期。返回 `orders` 以及 `total_cost_cents`。

各选项独立成单，保存各自赔率和玩法快照，沿用单注结算、资金冻结与佣金流程。所有订单、扣款、当期限额占用、待结算索引和幂等记录在一个事务内提交；任意一注失败时整批撤回。余额和本期累计限额按全部订单合计校验。相同用户、相同key和相同请求重试返回原订单，包括跨期或重启后的重试，不重复扣款；相同key更换内容会拒绝。

前端金额控件显示“每注金额”，总金额为每注金额乘选中数量。切换玩法和位置保留选择，正常跨期清空未提交选项。响应不确定时锁定选项、金额和场次，并用原期号与原请求重试确认；成功扣款后的余额刷新失败不会提示投注失败。

## 游戏控制统计重置

`POST /api/v1/admin/game-control/reset`：仅管理员可调用，提交 `{key}`。确认后将顶部今日盈亏、昨日盈亏、本月盈亏、当前总押注中金额四张卡片（含注数、投注、派彩、佣金）重新从零统计。服务端原子保存当前最大订单编号作为统计边界，重置后仅纳入新提交的订单；旧待结算订单后续正常结算但不重新进入这四项统计。边界持久化且对所有管理员生效，`GET /admin/game-control` 返回 `reset_at`。相同key重试返回原重置结果，不再次推进边界；每次新重置记入操作日志。

此操作不删除或修改订单、资金流水、余额、冻结资金、佣金和开奖记录；下方场次数据及订单管理继续显示完整数据。


备用网站：`GET /admin/domains` 显示主域名、服务器 IPv4、五个备用位置及状态；`PUT /admin/domains` 接受 `{version,domains:[五个域名或空字符串]}`；`POST /admin/domains/actions` 接受 `{version,index,action}`，index 为 0–4，每次仅操作一个域名，不支持批量，action 为 check / enable / disable。仅管理员可用，同源 JSON 保护及审计与其他后台接口一致。任务异步，返回 busy 后轮询 GET；不接受客户端 actor。服务未安装返回明确错误，不伪造 DNS/SSL 成功状态。部署及解析见 [备用网站部署文档](../../deploy/js18188/domains.md)。
