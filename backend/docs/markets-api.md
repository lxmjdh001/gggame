# 玩法、赔率与自动结算

## 玩法结构

每个场次独立配置赔率。用户界面分为“两面”和“常规”：两面集中列出各位置的大小单双、总和及适用的龙虎；常规按位置选择大小单双或指定数字。快3、PC蛋蛋另有和值数字。每次提交一个选项一注。用户直接输入金额或选择10/20/50/100/200/500元快捷金额，也可以设置自己的6个快捷金额；设置按用户保存在当前浏览器。

## 赔率口径

- 1.960 是**含本金总返还倍数**：投注100元中奖，返还196元；未中返还0；和局退回100元。
- `odds_milli` 是整数千分倍率，1960代表1.960。所有资金使用整数分；派彩向下取整到分，避免浮点资金误差。
- 两面与龙虎初始值1.960；分分彩三个场次的和（`dt.tie`）初始值8.000，投注100元中奖返还800元（含本金），不相等返还0。数字赔率不是核实过的同行报价，而是可编辑初始模板：等概率定位数字为 `0.98 × 可选数字数量`；快3/PC蛋蛋和值按 `0.98 / 对应和值概率`，截断为三位小数。模板不包含邀请佣金成本，也不保证各玩法合并后的经营收益。
- 后台支持每个场次、每个位置、每个选项分别修改赔率及启停，也可批量应用到当前筛选项。修改只影响新订单。
- 下单保存赔率、规则版本、玩法规则、三级邀请链和佣金比例；不得用后改赔率重算旧订单。前端提交旧赔率或旧单注金额，后端拒绝并要求重新确认。

## 接口

业务服务 `http://127.0.0.1:8082`，浏览器走同源 `/api`；统一响应 `{ "data": ... }`。

### 读取场次玩法与赔率

`GET /api/v1/markets/{session}`，公开只读。

```sh
curl http://127.0.0.1:8082/api/v1/markets/k3-1
```

返回 `session_id`、`markets[]`、`quotes[]`。玩法ID例如 `p1.big`、`p2.even`、`p3.n6`、`sum.n10`、`dt.dragon`。`markets` 含名称、位置、规则及版本；`quotes` 含 `market_id`、`odds_milli`、`enabled`。玩法ID需与场次联合使用。

### 管理员保存赔率

`PUT /api/v1/admin/markets/{session}`，需管理员登录。请求 `{ "quotes": [...] }`，必须带该场次完整、无重复的赔率表，不能仅传修改项。赔率允许1.000–1000.000（整数值1000–1000000）。事务保存，并记录修改前后审计日志。用户角色无权限修改。

### 提交一注

`POST /api/v1/market-orders`，需用户登录。

```json
{
  "session_id": "k3-1",
  "issue": "202610112201",
  "market_id": "p1.big",
  "odds_milli": 1960,
  "unit_cents": 200,
  "amount_cents": 1000,
  "key": "replace-with-unique-random-key"
}
```

示例期号需替换成该场次当前下一期。整分前10秒（如12:00:50）截止，后05秒（12:01:05）开奖；期间15秒不接新单，也不能提前买下一期。幂等key为16–100字符，一次逻辑下单使用一个key，失败重试使用同key同内容。服务端检查用户、余额、场次/选项开关、当前期号、封盘秒数、投注金额、起投金额、赔率和预计返还限额；扣款、订单、待结算索引在一个事务写入。请求不接受客户端指定的用户、派彩或上级链。

订单响应增加 `market_id`、`market_name`、`odds_milli`、`rule_snapshot`。结算后增加 `outcome`（win/lose/push）、`result_numbers`、`settled_at` 和 `payout_cents`。

## 自动结算与三级佣金

每期封盘后（50秒）固定当期订单清单，**开奖整分后00.010秒开始一次性预计算整期所有用户的自动订单**，目标在05秒内完成。例如12:10:00.010开始计算，12:10:05公布结果并入账。不再按人数或时间分批，也不设10人阈值。同一用户同一期的跨场次订单一起处理。后台每200ms检查计划，实际开始可能受调度略有延迟。


预计算从私有号码缓存取固定结果，按下单锁定的赔率与规则计算。结果只写入 `settlement_plans` / `prepared_payouts` 私有表；05秒前不改变余额、公开订单、流水、佣金或开奖记录。00:00日切时若当天号码尚未准备好，等待源数据到齐并补做整期计算；不会临时造数或换期。

05秒以后，必须读到对应场次已经公开的 `scheduled` 开奖，并验证其与预计算的结果摘要一致，才允许入账。正常情况下整期一次事务入账，同一用户当期全部自动订单、余额、流水、佣金和完成标记在同一事务提交。某个用户失败时回滚事务并拆分用户重试，让其他用户继续完成；重复调度、重启和多次调用不会重复入账。预计算后被撤销的订单跳过，不覆盖退款。结果或订单快照不一致时暂停该用户入账，记录错误等待处理。

断电重启后继续持久化计划；已提交用户跳过，未完成用户补处理。到05秒仍未完成时继续重试，不丢弃未完成订单；公布结果后也必须完成预计算和校验才能入账。只接受有效组别、期号、号码和规则版本；历史六批计划读取时合并为一次执行，已预计算和已入账用户的标记继续复用。旧版及六号单式人工结算订单不进入该自动队列。

判奖、派彩、流水、订单状态和最多三级佣金在同一个数据库事务完成。重复扫描或并发调用只生效一次。龙/虎遇和退本、撤销订单不产生有效投注佣金；“和”选项正常中奖或未中都按有效投注计算佣金；其他已结算订单按下单时三级比例计算，每级向下取整到分。管理员不能覆盖新玩法订单的派彩金额，可撤销待结算订单并退本；旧订单仍沿用人工流程。

## g8 与快3历史迁移

号码服务每天00:00为全天各分钟批次生成 g8：1–6可重复，共10个号码，原g1–g7不变。快3一分钟用1–3位，三分钟用8–10位，五分钟用4–6位。

源数据最新schema为4（全天预生成八组）；schema1/2/3历史保持原样，不补造旧期g8。业务库给快3建立新g8命名空间，每场首次生成100期1–6模拟历史；原g3的1–9快3记录保留在旧命名空间，当前场次接口不混读。模拟历史明确标识为 `simulated_history`，不参与资金结算。

## 直接金额与旧版倍数兼容

`amount_cents` 为整数分（例如500元传50000），支持精确到分，不要求是原单价的整数倍。直接金额模式必须省略 `multiplier` 或传0，不能同时指定正倍数。`unit_cents` 仍提交用户确认的当前起投额，设置变化时拒绝旧请求。订单记录中的 `cost_cents` 是实际扣款，金额模式 `multiplier=0`。旧版倍数请求继续按原倍数规则校验。

场次新增 `max_stake_cents`，初始单笔上限1000元（若既有起投额更高，则不低于该起投额），可在后台设置；下单严格校验金额不小于 `unit_cents` 且不超过上限。单笔上限最高可设100万元，不影响旧版倍数上限；赔率派彩限额仍独立生效。新增字段的升级会保留既有赔率、单价、倍数、佣金和封盘设置。

新增目录玩法在服务启动时补齐缺失赔率，不覆盖已配置倍率或暂停状态；迁移记入审计日志，重复启动不会重复添加。

## 一次性计算验证

`go test ./internal/accounts -run 'TestSinglePass|TestBatch' -count=1 -v` 使用30个用户、每人10笔订单（共300笔），并发执行真实下单函数，覆盖跨场次归并、00.010秒前不计算、一次处理所有用户、预计算后重启、05秒前不入账、四个重复结算工作者、退款跳过、结果/订单快照异常拒绝、单用户失败隔离及旧六批计划恢复。同时验证号码源到04.9秒才恢复时能够补算且不提前入账。跨年00:00期验证新年当天00:00:00.010开始计算。

账号由测试夹具建立，未测注册密码哈希和HTTP登录；测试数据不是整站并发容量承诺。数据库继续使用bbolt持久化事务。预计算和入账处理耗时不包含00.010秒至05秒之间的调度等待；存储或号码源故障时保留任务等待恢复，不保证硬实时截止。

## 六合彩完整规则 v6（2026-10-18）

八个六合彩场次、各自开奖周期、封盘时间和号码来源不变，仍为49选7、前六个正码加最后一个特码。玩法规则采用用户确认的 `lhc-rules-20261018.txt`。旧规则订单继续使用原快照，当前目录撤下的玩法不得新增下注，但已成功订单可幂等查询和重试。

### 分档报价与订单

三中二、二中特各为一个组选、一注本金，开奖后只选一个命中档位。三中二的档位为 `hit2`（两正码）、`hit3`（三正码）；二中特为 `special`（一正码加一特码）、`hit2`（两正码）。三中二的两正码加一特码只命中 `hit2`。

市场定义新增 `payout_tiers: [{key, label, default_odds_milli}]`。对应报价、单笔请求、批量请求中的每个 selection 和订单快照新增 `tier_odds_milli` 对象，必须携带全部且仅有定义中的档位。服务端核对每档价格后原子扣除一注本金并锁定整组报价。缺失、额外或已变更的档位报价均拒绝。此时 `odds_milli` 保留接口兼容，不作为分档派彩赔率；实际金额采用命中档的锁定赔率。

普通单档报价和订单不需要 `tier_odds_milli`。新增玩法和新增档位默认1.000；现有对应盘口自定义赔率与开关会迁移保留。后台可以分别调整两档。

### 次数派彩

正肖只统计前六个正码，所选生肖出现N次按锁定赔率派N次，仍只扣一次本金。结算记录包含 `payout_tier`、`payout_multiplier`、`payout_odds_milli`，供前后台解释本注金额；退本时返还一次本金。批量、开奖预演、预计算、发布入账及重算必须采用相同判奖函数。

### 49处理与范围

特码两面（包括合数、尾大小、大小单双组合、天地/前后/家野肖）、半波、半半波、合肖，以及正码1–6的大小单双、合数、尾大小，遇该位置49均退本金。指定号码、普通色波、特生肖/特头尾、五行、一肖/正肖/尾数/总肖、连肖连尾等按各自命中规则处理49，不能全局统一退本。

自选不中为5–11不中，连肖/连尾为2–5连。七色波的正码每球1分、特码1.5分；最高分并列时，颜色投注退本，和局投注中奖。总肖统计七球不同生肖数量。生肖对应沿用北京时间农历年，五行使用本次确认的固定号码表。
